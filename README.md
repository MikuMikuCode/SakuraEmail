# SakuraEmail 🌸

Telegram-бот для выдачи лицензионных ключей для макроса в мягком розовом стиле.

## Возможности

- `/start` регистрирует Telegram ID, тег и имя пользователя в локальной SQLite-базе;
- две роли: `creator` и `user`;
- кнопка `Мои ключи`;
- поиск ключей по Telegram ID в существующей Google Таблице;
- выдача всех неистекших и неотозванных ключей, новые строки показываются первыми;
- отображение вида подписки `Maket` или `MaketPro` из столбца `Вид`;
- ключи оформляются цитатой с моноширинным шрифтом;
- отдельная пометка для ключей со статусом `Использован`;
- заявки на ключ, техническую поддержку или другие вопросы;
- уведомление пользователя после выполнения заявки;
- личные сообщения зарегистрированным пользователям по Telegram-тегу;
- благодарности создателю не чаще одного раза в сутки;
- статистика благодарностей и отключаемые уведомления о них;
- панель создателя со статистикой, открытыми заявками и личными сообщениями;
- автоматическая рассылка нового ключа, когда старому осталось не более трех дней;
- защита от повторной рассылки одного продления;
- Dockerfile для будущего стороннего хостинга.

## Где находятся данные и секреты

В исходники не записываются:

- токен Telegram-бота;
- Telegram ID создателя;
- секрет Apps Script API;
- локальная база пользователей и заявок;
- логи и локальные выгрузки.

Секреты хранятся в `.env`, а персональные данные — в
`data/sakuraemail.sqlite3`. Оба пути исключены в `.gitignore` и
`.dockerignore`.

В SQLite сохраняются:

- Telegram ID, username и отображаемое имя;
- роль пользователя;
- текст и состояние заявок;
- благодарности и настройка уведомлений о них;
- SHA-256-отпечатки отправленных уведомлений.

Сами лицензионные ключи в SQLite не сохраняются. Они читаются из таблицы при
запросе и отправляются пользователю напрямую.

> `.gitignore` защищает только неотслеживаемые файлы. Перед первым будущим
> `git add` обязательно проверьте `git status` и убедитесь, что `.env` и
> `data/` отсутствуют в списке.

## Требования

- Python 3.11 или новее;
- Telegram-бот, созданный через BotFather;
- опубликованный Apps Script Web App;
- существующие листы `База данных` и `Лицензия`/`Лицензии`.

## Подготовка Telegram

1. Создайте бота через BotFather и получите токен.
2. Узнайте свой числовой Telegram ID — он станет `BOT_OWNER_ID`.
3. После запуска обязательно сами отправьте боту `/start`. Telegram не позволяет
   боту первым начать диалог даже с создателем.

## Подключение Apps Script

Выполните инструкцию [apps_script/INTEGRATION.md](apps_script/INTEGRATION.md).

Коротко:

1. Добавьте `BotApi.gs` в существующий Apps Script-проект.
2. Убедитесь, что `doPost` содержит действия `bot_get_keys` и
   `bot_expiring_renewals`.
3. Создайте Script Property `BOT_API_SECRET`.
4. Опубликуйте новую версию Web App.

## Локальный запуск в Windows

Откройте PowerShell в папке `SakuraEmail`:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполните `.env` реальными значениями, затем запустите:

```powershell
python -m bot
```

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен от BotFather |
| `BOT_OWNER_ID` | Числовой Telegram ID создателя |
| `APPS_SCRIPT_URL` | URL опубликованного Web App, заканчивающийся `/exec` |
| `BOT_API_SECRET` | Общий секрет бота и Script Properties, минимум 32 символа |
| `DATABASE_PATH` | Путь к SQLite, по умолчанию `data/sakuraemail.sqlite3` |
| `NOTIFICATION_POLL_SECONDS` | Частота поиска уведомлений, по умолчанию 3600 секунд |

## Логика выдачи ключей

Apps Script выбирает строки по `Telegram ID` и оставляет только ключи:

- с будущим дедлайном;
- со статусом `Свободен` или `Использован`;
- не имеющие статуса `Истек`, `Истёк` или `Отозван*`.

Если таких строк несколько, бот показывает все, начиная с последней строки
таблицы. Для каждого ключа выводятся вид подписки, статус и дата в формате
`ДД.ММ.ГГГГ ЧЧ:ММ:СС`. Если подходящих строк нет, выводится
`Активных ключей нет`.

Для использованного ключа бот дополнительно пишет:

```text
Ключ уже был использован. Для запроса нового оставьте заявку
```

Кнопка `Оставить заявку` доступна при любом статусе ключа и даже при отсутствии
активных ключей. Она переводит пользователя в режим ввода запроса; ввод можно
прервать кнопкой `Отменить`. Заявка сохраняется в SQLite и отправляется
создателю с тегом и Telegram ID. После нажатия создателем кнопки `Выполнено`
пользователь получает сообщение о закрытии заявки.

## Уведомления о продлении

Фоновая задача раз в `NOTIFICATION_POLL_SECONDS` запрашивает таблицу.
Уведомление отправляется только когда одновременно выполнены условия:

1. текущий ключ закончится не позднее чем через три дня;
2. в более новой строке уже есть свободный неистекший ключ;
3. пользователь ранее запустил бота через `/start`;
4. эта пара старого и нового ключа еще не рассылалась.

Если нового ключа нет, бот ничего не отправляет.

## Панель создателя

У пользователя с ID из `BOT_OWNER_ID` появляется кнопка `⚙️ Управление`:

- `📊 Статистика` — количество пользователей и открытых заявок;
- `💌 Заявки` — список заявок с кнопкой `Выполнено`;
- `✉️ Написать пользователю` — сначала запрашивает Telegram-тег, затем текст
  сообщения. Получатель должен ранее запустить бота через `/start`.

## Благодарности

Обычный пользователь может нажать `Спасибо!` не чаще одного раза за 24 часа.
Если уведомления включены, создатель сразу получает сообщение с тегом
пользователя. Для создателя кнопка `Спасибо!` открывает статистику за текущий
день по московскому времени и за всё время, а также позволяет включать и
отключать такие уведомления.

## Docker

После заполнения переменных окружения проект можно проверить локально:

```powershell
docker build -t sakuraemail .
docker run --rm --env-file .env -v "${PWD}/data:/app/data" sakuraemail
```

На хостинге SQLite-файл должен находиться на постоянном диске/volume. Без
постоянного хранилища пользователи, заявки и история уведомлений исчезнут после
перезапуска контейнера.

## Перед будущей публикацией в Git

1. Не добавляйте `.env`.
2. Не добавляйте папку `data`.
3. Не добавляйте JSON сервисных аккаунтов, токены и выгрузки таблицы.
4. Если секрет когда-либо попал в коммит, одного удаления файла недостаточно —
   токен или секрет необходимо сразу перевыпустить.
5. На хостинге задавайте значения через панель Environment Variables/Secrets.
