# SakuraEmail 🌸

Telegram-бот для выдачи лицензионных ключей и ежедневных рабочих отчётов
сотрудников в мягком розовом стиле.

## Возможности

- `/start` регистрирует Telegram ID, тег и имя пользователя в локальной SQLite-базе;
- две роли: `creator` и `user`;
- кнопки `Отчет` и `Ключи` в одной строке, а также `Настройки`;
- поиск ключей по Telegram ID в существующей Google Таблице;
- выдача всех неистекших и неотозванных ключей, новые строки показываются первыми;
- отображение вида подписки `Maket` или `MaketPro` из столбца `Вид`;
- ключи оформляются цитатой с моноширинным шрифтом;
- отдельная пометка для ключей со статусом `Использован`;
- заявки на ключ, техническую поддержку или другие вопросы;
- уведомление пользователя после выполнения заявки;
- личные сообщения зарегистрированным пользователям по Telegram-тегу;
- благодарности создателю не чаще одного раза в сутки;
- статистика благодарностей и отключаемые уведомления о них;
- панель создателя со статистикой, открытыми заявками и личными сообщениями;
- личный кабинет с ФИО, рабочим графиком и баллами за сегодня, текущую неделю
  и текущий месяц;
- ежедневный отчёт по оригинальным макетам в формате `FGR 12, SNB 6`;
- проверка артикулов и коэффициентов по листу `Множители`;
- сохранение и замена отчётов в листе `Баллы за макет` без локальной копии
  транзакций;
- изменение отчёта за сегодня или один из двух предыдущих календарных дней;
- индивидуальный график работы и отключаемое напоминание за 30 минут до его
  окончания с понедельника по пятницу;
- автоматическая рассылка нового ключа, когда старому осталось не более трех дней;
- защита от повторной рассылки одного продления;
- Dockerfile для будущего стороннего хостинга.

## Где находятся данные и секреты

В исходники не записываются:

- токен Telegram-бота;
- Telegram ID создателя;
- секрет Apps Script API;
- локальная база пользователей и заявок;
- логи и локальные выгрузки.

Секреты хранятся в `.env`, а персональные данные — в
`data/sakuraemail.sqlite3`. Оба пути исключены в `.gitignore` и
`.dockerignore`.

В SQLite сохраняются:

- Telegram ID, username и отображаемое имя;
- роль пользователя;
- текст и состояние заявок;
- благодарности и настройка уведомлений о них;
- рабочий график и переключатель напоминаний об отчёте;
- SHA-256-отпечатки отправленных уведомлений и отметки, защищающие рабочее
  напоминание от повтора в тот же день.

Сами лицензионные ключи в SQLite не сохраняются. Они читаются из таблицы при
запросе и отправляются пользователю напрямую.

Строки ежедневных отчётов и рассчитанные по ним баллы также не сохраняются в
SQLite. Единственный источник этих данных — Google Таблица. До подтверждения
отчёт существует только во временном состоянии диалога бота.

> `.gitignore` защищает только неотслеживаемые файлы. Перед первым будущим
> `git add` обязательно проверьте `git status` и убедитесь, что `.env` и
> `data/` отсутствуют в списке.

## Требования

- Python 3.11 или новее;
- Telegram-бот, созданный через BotFather;
- опубликованный Apps Script Web App;
- существующие листы `База данных`, `Лицензия`/`Лицензии`, `Множители` и
  `Баллы за макет`.

## Подготовка Telegram

1. Создайте бота через BotFather и получите токен.
2. Узнайте свой числовой Telegram ID — он станет `BOT_OWNER_ID`.
3. После запуска обязательно сами отправьте боту `/start`. Telegram не позволяет
   боту первым начать диалог даже с создателем.

## Подключение Apps Script

Выполните инструкцию [apps_script/INTEGRATION.md](apps_script/INTEGRATION.md).

Коротко:

1. Добавьте `BotApi.gs` в существующий Apps Script-проект.
2. Убедитесь, что `doPost` содержит действия `bot_get_keys`,
   `bot_expiring_renewals`, `bot_work_profile`, `bot_report_catalog`,
   `bot_get_report` и `bot_save_report`.
3. Создайте Script Property `BOT_API_SECRET`.
4. Опубликуйте новую версию Web App.

## Локальный запуск в Windows

Откройте PowerShell в папке `SakuraEmail`:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполните `.env` реальными значениями, затем запустите:

```powershell
python -m bot
```

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен от BotFather |
| `BOT_OWNER_ID` | Числовой Telegram ID создателя |
| `APPS_SCRIPT_URL` | URL опубликованного Web App, заканчивающийся `/exec` |
| `BOT_API_SECRET` | Общий секрет бота и Script Properties, минимум 32 символа |
| `DATABASE_PATH` | Путь к SQLite, по умолчанию `data/sakuraemail.sqlite3` |
| `NOTIFICATION_POLL_SECONDS` | Частота поиска уведомлений, по умолчанию 3600 секунд |

## Логика выдачи ключей

Apps Script выбирает строки по `Telegram ID` и оставляет только ключи:

- с будущим дедлайном;
- со статусом `Свободен` или `Использован`;
- не имеющие статуса `Истек`, `Истёк` или `Отозван*`.

Если таких строк несколько, бот показывает все, начиная с последней строки
таблицы. Для каждого ключа выводятся вид подписки, статус и дата в формате
`ДД.ММ.ГГГГ ЧЧ:ММ:СС`. Если подходящих строк нет, выводится
`Активных ключей нет`.

Для использованного ключа бот дополнительно пишет:

```text
Ключ уже был использован. Для запроса нового оставьте заявку
```

Кнопка `Оставить заявку` доступна при любом статусе ключа и даже при отсутствии
активных ключей. Она переводит пользователя в режим ввода запроса; ввод можно
прервать кнопкой `Отменить`. Заявка сохраняется в SQLite и отправляется
создателю с тегом и Telegram ID. После нажатия создателем кнопки `Выполнено`
пользователь получает сообщение о закрытии заявки.

## Таблица для ежедневных отчётов

Сотрудники не заводятся в отдельной базе бота. Профиль определяется по
`Telegram ID` в листе `База данных`, а ФИО берётся из той же строки. В личном
кабинете последнее слово полного ФИО считается отчеством и не показывается.

> Владелец бота — такой же участник системы отчётов. Строка с его
> `BOT_OWNER_ID` обязательно должна присутствовать в листе `База данных`,
> иначе Apps Script не сможет найти рабочий профиль и сохранить отчёт.

Лист `Множители` содержит справочник видов макетов, начиная со строки 2:

| Столбец | Содержимое |
|---|---|
| B | Код артикула, например `FGR` или `SNB` |
| D | Положительный числовой коэффициент |

Лист `Баллы за макет` хранит по одной строке на каждый вид макета в отчёте:

| Столбец | Содержимое | Кто заполняет |
|---|---|---|
| A | Дата и время отчёта по Москве | Apps Script |
| B | ФИО | Формула таблицы |
| C | Telegram-тег | Формула таблицы |
| D | Telegram ID | Apps Script |
| E | Артикул | Apps Script |
| F | Количество | Apps Script |

Бот и Apps Script записывают и очищают **только A, D, E и F**. Столбцы B и C
должны заполняться `ARRAYFORMULA` на весь столбец либо заранее протянутыми
формулами для всех возможных строк. При добавлении отчёта с несколькими
артикулами значения A и D повторяются.

Баллы вычисляются как `количество × текущий коэффициент`. В существующей схеме
коэффициент не записывается в строку транзакции, поэтому изменение коэффициента
в `Множители!D:D` **ретроактивно изменит исторические баллы**, включая
прошедшие расчётные периоды.

## Ежедневный отчёт

Кнопка `Отчет` предлагает посчитать только оригинальные макеты. Допустимы один
или несколько элементов, например:

```text
FGR 12
FGR 12, SNB 6
```

Коды проверяются по листу `Множители`, а количество должно быть положительным
целым числом. Неизвестный артикул не сохраняется: бот сообщает об отсутствующем
виде макета и продолжает ждать исправленный ввод.

Перед записью бот показывает дату и список `артикул · количество`, после чего
предлагает `Отменить`, `Изменить` или `✅ Отправить`. Черновиков и проверки
руководителем нет. После подтверждения `bot_save_report` сразу заменяет в
Google Таблице весь отчёт этого сотрудника за выбранный день. Повторная отправка
не добавляет второй отчёт: прежние строки за этот день заменяются, а лишние
строки очищаются только в столбцах A, D, E и F.

## Личный кабинет и изменение отчётов

Раздел `Настройки` показывает сокращённое ФИО, график, состояние уведомлений и
баллы за сегодня, текущую неделю и текущий месяц. Статистика каждый раз
рассчитывается по данным Google Таблицы и текущим коэффициентам; отчётные
транзакции для неё не копируются в SQLite.

Из кабинета можно изменить график, включить или выключить рабочие напоминания и
открыть старый отчёт. Для редактирования доступны ровно три московские
календарные даты: сегодня и два предыдущих дня. Ограничение проверяет Apps
Script, поэтому устаревшую дату нельзя сохранить обходным запросом. Если строк
за выбранный день нет, бот сообщает `В этот день отчета не было`; кнопка
`Изменить` позволяет создать отчёт за эту доступную дату.

## Рабочий график и напоминания об отчёте

По умолчанию рабочий график — `09:00–18:00 мск`, а напоминания включены.
Настройки времени и переключатель напоминаний сохраняются в SQLite, но сами
отчёты остаются только в Google Sheets.

С понедельника по пятницу бот проверяет наличие отчёта за текущую московскую
дату. Если отчёта ещё нет, за 30 минут до индивидуального конца смены приходит:

```text
🌸 До конца рабочего дня осталось полчаса!
Не забудь заполнить баллы (｡•̀ᴗ-)✧
```

Для стандартного графика это `17:30 мск`. После отправки отчёта напоминание не
приходит; локальная отметка не позволяет повторить его в тот же день.

## Уведомления о продлении

Фоновая задача раз в `NOTIFICATION_POLL_SECONDS` запрашивает таблицу.
Уведомление отправляется только когда одновременно выполнены условия:

1. текущий ключ закончится не позднее чем через три дня;
2. в более новой строке уже есть свободный неистекший ключ;
3. пользователь ранее запустил бота через `/start`;
4. эта пара старого и нового ключа еще не рассылалась.

Если нового ключа нет, бот ничего не отправляет.

## Панель создателя

У пользователя с ID из `BOT_OWNER_ID` появляется кнопка `⚙️ Управление`:

- `📊 Статистика` — количество пользователей и открытых заявок;
- `💌 Заявки` — список заявок с кнопкой `Выполнено`;
- `✉️ Написать пользователю` — сначала запрашивает Telegram-тег, затем текст
  сообщения. Получатель должен ранее запустить бота через `/start`.

## Благодарности

Обычный пользователь может нажать `Спасибо!` не чаще одного раза за 24 часа.
Если уведомления включены, создатель сразу получает сообщение с тегом
пользователя. Для создателя кнопка `Спасибо!` открывает статистику за текущий
день по московскому времени и за всё время, а также позволяет включать и
отключать такие уведомления.

После отправки благодарности пользователь может нажать `Добавить` и написать
к ней один комментарий. Комментарий всегда отправляется создателю с тегом
пользователя, даже если обычные уведомления о благодарностях отключены. Ввод
комментария можно прервать кнопкой `Отменить`.

## Docker

После заполнения переменных окружения проект можно проверить локально:

```powershell
docker build -t sakuraemail .
docker run --rm --env-file .env -v "${PWD}/data:/app/data" sakuraemail
```

На хостинге SQLite-файл должен находиться на постоянном диске/volume. Без
постоянного хранилища пользователи, заявки и история уведомлений исчезнут после
перезапуска контейнера.

## Перед будущей публикацией в Git

1. Не добавляйте `.env`.
2. Не добавляйте папку `data`.
3. Не добавляйте JSON сервисных аккаунтов, токены и выгрузки таблицы.
4. Если секрет когда-либо попал в коммит, одного удаления файла недостаточно —
   токен или секрет необходимо сразу перевыпустить.
5. На хостинге задавайте значения через панель Environment Variables/Secrets.
