# Подключение Apps Script API

Бот не подключается к Google Sheets напрямую. Он обращается к существующему
Apps Script Web App по HTTPS. Действия бота защищены отдельным секретом.

В текущей структуре столбец F называется `Лицензия` на листе `База данных` и
`Вид лицензии` на листе `Лицензия`. Оба названия поддерживаются; также скрипт
понимает старые заголовки `Вид` и `Тип`. Значениями остаются `Maket` и
`MaketPro`. Генерация, продление и поиск нового ключа всегда выполняются внутри
одного вида. Значения `Preview` и `PreviewPro` пока не обрабатываются.

Старые версии VBA-модуля отправляют поле `product: "DisMaket"`. Это имя
макроса, а не вид лицензии, поэтому Apps Script не использует `product` при
выборе `Maket`/`MaketPro`. Явно ограничить вид может только новое поле
`license_type` (или совместимые `licenseType`/`type`); без него вид определяется
по найденному ключу. Это необходимо для обратной совместимости уже выданных
лицензий.

Ответы `bot_get_keys` и `bot_expiring_renewals` содержат поле
`license_type`; Python-бот можно обновить для его показа отдельным этапом.

Тот же Web App обслуживает ежедневные отчёты сотрудников. Для них используются
действия `bot_work_profile`, `bot_report_catalog`, `bot_get_report` и
`bot_save_report`. Все они принимают общий `BOT_API_SECRET` и работают с той же
таблицей, что и лицензии.

Доступ к самому боту проверяется действием `bot_access_snapshot`. Оно возвращает
все заполненные Telegram ID и отметку блокировки. Отметка `Заблокирован` читается
строго из столбца B листа `База данных`; любые другие значения в B не ограничивают
доступ. Если один ID встречается несколько раз, блокировка хотя бы в одной строке
имеет приоритет.

## Подготовьте листы рабочих отчётов

### `База данных`

Рабочий профиль определяется по `Telegram ID`, а имя берётся из столбца `ФИО`.
Последнее слово ФИО из трёх и более слов считается отчеством и не показывается
в кратком профиле.

> В листе обязательно должна быть строка с Telegram ID владельца из
> `BOT_OWNER_ID`. Наличие роли `creator` только в SQLite недостаточно: без строки
> в `База данных` владелец не получит рабочий профиль и не сможет сохранить
> отчёт.

### `Множители`

Первая строка остаётся заголовком, данные начинаются со строки 2:

| Столбец | Значение |
|---|---|
| B | Код артикула, например `FGR` |
| D | Положительный числовой коэффициент |

Пустые строки и строки без корректного положительного коэффициента не входят в
каталог. Коды нормализуются в верхний регистр.

### `Баллы за макет`

Первая строка содержит заголовки. Рабочие столбцы имеют фиксированное значение:

| Столбец | Значение | Источник |
|---|---|---|
| A | Дата и время отчёта | Apps Script |
| B | ФИО | Формула Google Sheets |
| C | Telegram-тег | Формула Google Sheets |
| D | Telegram ID | Apps Script |
| E | Артикул | Apps Script |
| F | Количество оригинальных макетов | Apps Script |

Apps Script записывает и очищает **только A, D, E и F**. Для одного отчёта A и
D повторяются в каждой строке артикула. Столбцы B и C должны иметь
`ARRAYFORMULA`, охватывающую весь столбец данных, либо заранее протянутые
формулы во всех доступных строках. Если скрипт добавит новую строку, обычная
формула из предыдущей строки автоматически туда не скопируется.

При сохранении скрипт ищет все строки по Telegram ID и московской календарной
дате, затем заменяет весь набор артикулов. Он не дописывает вторую версию того
же отчёта. Лишние старые позиции очищаются только в A, D, E и F, чтобы не
повредить формулы.

Баллы профиля рассчитываются по сохранённым количествам и **текущим** значениям
`Множители!D:D`. Коэффициент не фиксируется в транзакции, поэтому его изменение
ретроактивно пересчитает исторические баллы. Если для расчёта зарплаты нужна
неизменяемая история, текущую схему A/D/E/F потребуется отдельно расширить
снимком коэффициента или готового количества баллов.

## 1. Добавьте файл

В том же Apps Script-проекте, где находится текущий код лицензирования:

1. Нажмите `+` рядом с `Files`.
2. Создайте Script-файл с именем `BotApi`.
3. Вставьте содержимое `BotApi.gs`.

## 2. Добавьте маршруты в doPost

В существующей функции `doPost`, после обработки `validate`, должны находиться
все маршруты бота:

```javascript
if (action === 'bot_get_keys') {
  return json_(botGetKeys_(payload));
}

if (action === 'bot_expiring_renewals') {
  return json_(botExpiringRenewals_(payload));
}

if (action === 'bot_access_snapshot') {
  return json_(botGetAccessSnapshot_(payload));
}

if (action === 'bot_work_profile') {
  return json_(botGetWorkProfile_(payload));
}

if (action === 'bot_report_catalog') {
  return json_(botGetReportCatalog_(payload));
}

if (action === 'bot_get_report') {
  return json_(botGetWorkReport_(payload));
}

if (action === 'bot_save_report') {
  return json_(botSaveWorkReport_(payload));
}
```

В рабочем файле `license_basis/apps_script/Code.txt` эти маршруты уже добавлены.

Для рабочих отчётов основной код также задаёт:

```javascript
const WORK_REPORT_SHEET_NAMES = ['Баллы за макет'];
const WORK_MULTIPLIER_SHEET_NAMES = ['Множители'];
const WORK_TIME_ZONE = 'Europe/Moscow';
const WORK_REPORT_EDIT_DAYS = 3;
```

В настройках самой Google Таблицы и Apps Script-проекта установите часовой пояс
`Europe/Moscow` (GMT+03:00). Код явно использует московский пояс для границ
дней, но одинаковая настройка таблицы особенно важна для корректного отображения
значений даты и времени в столбце A.

## 3. Контракт действий рабочих отчётов

Каждый запрос отправляется методом POST в JSON и содержит `action`, `secret` и
поля выбранного действия.

### `bot_access_snapshot`

Не принимает пользовательских полей. Возвращает массив `users` с полями
`telegram_id` и `blocked`. Python-бот обновляет этот снимок не чаще одного раза
в три дня и хранит его в локальной SQLite-базе. ID без строки в `База данных` и
ID с отметкой `Заблокирован` в столбце B не получают доступ к функциям бота и не
включаются в фоновые или массовые рассылки. Статусы `Активен`, `Неактивен`,
`Пробный` и любые другие значения не участвуют в этой проверке.

### `bot_work_profile`

Принимает `telegram_id`. Ищет сотрудника в `База данных` и возвращает:

- `found`, `full_name` и сокращённое `display_name`;
- `stats.today` — баллы за текущую московскую дату;
- `stats.week` — баллы с понедельника по текущую дату;
- `stats.month` — баллы с первого числа текущего месяца.

Статистика вычисляется непосредственно по `Баллы за макет` и текущему каталогу
`Множители`; SQLite в расчёте не участвует.

### `bot_report_catalog`

Принимает `telegram_id`. Проверяет, что сотрудник присутствует в `База данных`,
и возвращает `found` и массив `items` с полями `article` и `coefficient` из
столбцов B и D листа `Множители`.

### `bot_get_report`

Принимает `telegram_id` и `report_date` в формате `YYYY-MM-DD`. Возвращает
`found`, `editable`, нормализованную `report_date` и массив `items` с полями
`article` и `quantity`. Если старые данные содержат несколько одинаковых
артикулов за день, количества агрегируются.

Редактируемы ровно три московские календарные даты: сегодня и две предыдущие.
Например, 14 октября доступны 12, 13 и 14 октября. Выходные из окна не
исключаются.

### `bot_save_report`

Принимает `telegram_id`, `report_date` в формате `YYYY-MM-DD` и массив:

```json
{
  "items": [
    {"article": "FGR", "quantity": 12},
    {"article": "SNB", "quantity": 6}
  ]
}
```

Количество должно быть положительным целым числом, а каждый артикул должен
присутствовать в `Множители`. Сервер повторно проверяет сотрудника, каталог и
трёхдневное окно, даже если Python-бот уже выполнил эти проверки. При успехе
действие под блокировкой заменяет весь отчёт за выбранный день и возвращает
`saved: true`. Неизвестные коды возвращаются в `unknown_articles` без частичной
записи.

## 4. Проверьте границу хранения и напоминания

Ежедневные отчёты хранятся только в листе `Баллы за макет`. Python-бот не
создаёт для них локальную таблицу и при показе истории или статистики заново
обращается к Apps Script.

В SQLite остаются только служебные данные рабочего интерфейса:

- начало и конец индивидуального графика;
- переключатель рабочих напоминаний;
- отметка об обработанном напоминании для защиты от повторной отправки.

Значения по умолчанию — `09:00–18:00 мск`, уведомления включены. С понедельника
по пятницу бот за 30 минут до индивидуального конца смены проверяет отчёт за
текущую московскую дату. Если отчёта нет, сотрудник получает напоминание; при
стандартном графике оно приходится на `17:30 мск`. Изменение локального графика
не изменяет даты и строки в Google Sheets.

## 5. Создайте секрет

Сгенерируйте случайную строку длиной не менее 32 символов. Например, локально:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

В Apps Script откройте `Project Settings -> Script Properties` и добавьте:

```text
BOT_API_SECRET = сгенерированная строка
```

Ту же строку положите в локальный `.env` бота. Не вставляйте ее в `.gs`,
README, сообщения или будущий Git-репозиторий.

## 6. Опубликуйте новую версию

1. `Deploy -> Manage deployments`.
2. Откройте текущее Web App-развертывание.
3. Выберите `New version`.
4. Нажмите `Deploy`.
5. Убедитесь, что URL `/exec` совпадает с `APPS_SCRIPT_URL` в `.env`.

Простого сохранения исходника недостаточно: `/exec` продолжит выполнять старую
версию, пока развертывание не обновлено.
